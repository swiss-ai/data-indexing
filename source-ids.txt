sources[].id field — per-dataset reference
==========================================

Each ES document has a sources[] array. The "id" field within each source entry
is what's documented here — it is NOT the ES document _id (which is always
SHA256(text) for every dataset).

─────────────────────────────────────────────────────────────────
AGGREGATED DATASETS  (indexed via index_aggregated.py)
─────────────────────────────────────────────────────────────────
These datasets are Spark-deduplicated before indexing. The sources[] array
is built by Spark and the id values come from the original dataset's id column.

  fineweb-1        Native FineWeb id — unique URN-style identifiers assigned
                   by the FineWeb team (e.g. "<urn:...>"). Guaranteed unique.

  fineweb-edu      Same id scheme as FineWeb-1. Unique per document.

  dclm             Native DCLM id from the dataset's id column. Unique.

  fineweb-2        Native FineWeb-2 id. Same URN-style scheme as FineWeb-1.
                   Unique per document.

─────────────────────────────────────────────────────────────────
RAW DATASETS  (indexed via index_raw.py)
─────────────────────────────────────────────────────────────────

  europarl         id column from parquet. Native dataset ID assigned during
                   preprocessing of the EuroParl parallel corpus.

  paradocs         id column from parquet. Native dataset ID.

  euroblocks       id column from parquet. Native dataset ID.

  institutional-   id column from parquet. Native dataset ID from the
  books            institutional books preprocessing pipeline.

  finemath         id column from parquet. Native FineMath ID.

  infiwebmath      id column from parquet. Native InfiWebMath ID.

  megamath-web     id column from parquet. Native MegaMath-Web ID.

  starcoder        id column from parquet. Native StarCoder ID (typically
                   encodes the GitHub repository + file path).

  starcoder-       id column from parquet. Same scheme as starcoder.
  extras

  wikipedia        url field (there is no id column in the Wikipedia parquet).
                   The article URL doubles as the unique identifier.

  flan             id column from parquet. Native FLAN dataset ID.

  gutenberg        Synthesized: "{parquet_filename}:{line_number_in_file}"
                   The raw JSONL has no id field so one is constructed at
                   index time from the file name and line position.

  canaries         canary_idx integer from the JSONL record. This is the
                   canary sequence number (not a hash).

  stackv2-edu      id field from the JSONL record. Native Stack-v2-edu ID.

  alignment        Synthesized: "{shard_filename}:{row_within_shard}"
                   e.g. "alignment-merged-0003.parquet:12741"
                   Open the named shard file and read row N directly.
                   Parquet shards are stored at:
                   /capstor/store/cscs/swissai/a145/es_indices_2026/
                     posttrain_preprocessing/alignment-v2/
                   Both 8B and 70B model responses are included (v2,
                   2026-06-30). Earlier v1 used conversation_id as the
                   dedup key, incorrectly dropping same-prompt/different-
                   response pairs.

  sft-mixture      Synthesized: "{shard_filename}:{row_within_shard}"
                   e.g. "sft-merged-0007.parquet:23104"
                   Open the named shard file and read row N directly.
                   Parquet shards are stored at:
                   /capstor/store/cscs/swissai/a145/es_indices_2026/
                     posttrain_preprocessing/sft-mixture-v2/
                   All conversations included (v2, 2026-06-30).
                   Earlier v1 used conversation_id as the dedup key,
                   incorrectly dropping same-prompt/different-response pairs.

─────────────────────────────────────────────────────────────────
NOTES
─────────────────────────────────────────────────────────────────
* The ES document _id is always SHA256(text), regardless of dataset.
  sources[].id is provenance information only — it links back to the
  source dataset's own identifier for that document.

* For aggregated datasets a single ES document can have multiple entries
  in sources[] (one per dataset the text appeared in). Each entry has
  its own id from that dataset.

* Both alignment and sft-mixture were reprocessed on 2026-06-30 to fix a
  bug where conversation_id was used as the dedup key. Same conversation_id
  does not imply same text — the same prompt can have multiple distinct
  model responses. SHA256(text) is the correct unique key.
